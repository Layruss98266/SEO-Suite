What Is SEO Suite?

SEO Suite is a self-hosted web application you run on your own server or laptop. It combines a real Chromium browser (via Playwright) for accurate Google-indexing checks with a comprehensive 4-phase SEO audit engine covering everything from robots.txt to Core Web Vitals to backlink authority — all in one unified dark-themed dashboard.

🕷️
Real Browser Checks
Chromium renders each URL exactly as Googlebot sees it — no fake user-agents, no guesswork.
📊
28-Point Audits
4 phases: Technical SEO, PageSpeed, Search Console, and Authority — all in a single run.
⚡
Live Streaming
Server-Sent Events push real-time progress directly to your browser — no polling required.
🛠️
17+ Standalone Tools
Schema validator, IndexNow submit, sitemap audit, SERP preview, redirect chains, and more.
📄
Rich Reports
Export to HTML, Excel, CSV, or PDF. Compare two audit runs side-by-side for delta tracking.
🔐
Production Security
SSRF protection, rate limiting, bcrypt auth, CORS lockdown, and DNS-rebinding guards built-in.

Quick Start

Be up and running in under 5 minutes on any machine with Python 3.10+.

# 1. Clone the repository
git clone https://github.com/your-org/seo-suite.git
cd seo-suite

# 2. Create and activate a virtual environment
python -m venv .venv
.venv\Scripts\activate        # Windows
source .venv/bin/activate      # macOS / Linux

# 3. Install all dependencies
pip install -r requirements.txt

# 4. Install the Chromium browser (one-time)
playwright install chromium

# 5. Start the server
python main.py
✓ Open http://localhost:8080 in your browser. The dashboard loads immediately — no database setup, no migrations.
ℹ No auth by default: The dashboard is open on localhost only. To enable password protection for shared / remote access, see the Authentication section.

Step-by-Step Installation

Install Python dependencies
pip install -r requirements.txt

This installs Flask, Playwright, BeautifulSoup4, Pandas, openpyxl, Google API client, Sentry SDK, flask-limiter, and ~30 other packages.

Install Chromium browser
playwright install chromium

Downloads a ~130 MB headless Chromium binary. Required only for the Indexing Checker feature. All other tools work without it.

Copy and edit the environment file
cp .env.example .env
# Then open .env and fill in any API keys you have

All fields are optional — the app works without any API keys, but features like PageSpeed analysis and Search Console data require them.

Start the server
# Development (auto-reload)
python main.py

# Production (Waitress WSGI, no reload)
python main.py --no-reload

# Production (Gunicorn, Linux only)
gunicorn -w 1 -b 0.0.0.0:8080 dashboard:app

Updating

git pull origin main
pip install -r requirements.txt   # pick up new packages
python main.py

Authentication

By default, SEO Suite binds to 127.0.0.1 (localhost only) with no password — safe for local dev. Enable auth before exposing on a network or cloud host.

Enable Password Protection

Generate a bcrypt password hash
python -c "from werkzeug.security import generate_password_hash; print(generate_password_hash('yourpassword'))"

Copy the output — it looks like pbkdf2:sha256:260000$...

Add to your .env file
SEO_SUITE_USERNAME=admin
SEO_SUITE_PASSWORD_HASH=pbkdf2:sha256:260000$...
SEO_SUITE_SECRET=change-this-to-32-random-characters-minimum
Expose on network (optional)
SEO_SUITE_HOST=0.0.0.0   # listen on all interfaces
SEO_SUITE_COOKIE_SECURE=1 # only over HTTPS
⚠ Never expose on 0.0.0.0 without enabling auth and placing an nginx/Caddy reverse proxy in front. The dashboard can trigger real browser sessions and external HTTP requests.

SEO Audit Engine

The audit engine runs up to 28 individual checks across 4 phases. Each phase is independent — you can enable only the phases you have API keys for.

Phase 1 — Technical
  • robots.txt compliance
  • HTTP status codes
  • Redirect chains
  • Canonical tags
  • Title & meta description
  • H1 / H2 headings
  • Image alt text
  • Word count
  • Broken internal links
  • Internal link graph
  • XML sitemap presence
  • JSON-LD structured data
  • Hreflang tags
  • TTFB measurement
Free — No API key
Phase 2 — Performance
  • PageSpeed score (mobile + desktop)
  • Core Web Vitals (LCP, FID, CLS)
  • Mobile friendliness
  • GZIP compression
  • Cache-Control headers
  • HSTS enforcement
Requires PageSpeed API key
Phase 3 — Search Console
  • Clicks & impressions (90 days)
  • Average position
  • CTR per URL
  • Coverage errors
  • Top queries per page
  • Sitemap submission status
Requires GSC OAuth
Phase 4 — Authority
  • Backlink count
  • Domain Authority score
  • Keyword rankings
  • SERP snippet preview
Requires Moz / DataForSEO

Running an Audit

  1. Navigate to SEO Audit in the sidebar
  2. Choose input type: single URL, domain, sitemap, or CSV
  3. Select audit phases (all 4 are on by default)
  4. Set the URL limit and number of parallel workers (1–8)
  5. Click Run Audit — progress streams live in the dashboard
  6. When complete, click Export to download as HTML, Excel, or PDF

Bulk Use Case Runs

Upload a CSV of URLs and run any use case against all of them in a single click. Results appear in a unified table — sortable by score, issue count, or any metric. Limit is 20 URLs per bulk run to prevent server overload.

Reports & Exports

Every completed audit and indexing run is saved to disk and accessible via the Reports panel.

Report Formats

HTML Report

Fully self-contained HTML file with embedded CSS and charts. Open in any browser, share by email, or host as a static file. Includes a per-URL breakdown, summary cards, and issue lists.

Excel / CSV Export

Multi-sheet XLSX with summary, per-URL data, issue list, and raw check results. CSV exports are single-sheet for easy import into Google Sheets or Looker.

PDF Export

Rendered via headless Chromium — identical to the HTML report but as a downloadable PDF. Useful for client deliverables. Capped at 2 concurrent renders to prevent OOM.

Compare Two Runs

Select any two saved reports and generate a diff: newly indexed / de-indexed URLs, changed scores, new issues introduced. Great for tracking improvement over time.

Automated Scheduling

Run indexing or audit checks on a timer — useful for monitoring campaigns without manual intervention.

Setup via Settings Panel

  1. Open Settings → Schedule
  2. Toggle Enabled to true
  3. Set interval_hours (e.g. 24 for daily)
  4. Optionally set run_time (e.g. "02:00" for 2 AM)
  5. Enter your sitemap URL and URL limit
  6. Configure Notifications to receive results by email/Slack
⚠ Scheduling uses an in-process thread. For production reliability on Linux, use cron to call python main.py --run-once instead of the built-in scheduler.

Schema Validator

Paste any URL and the validator fetches the page, extracts every <script type="application/ld+json"> block, parses it, and checks it against Schema.org required-field rules.

Supported Schema Types

Article NewsArticle BlogPosting Product FAQPage BreadcrumbList LocalBusiness Organization Person VideoObject Event HowTo Recipe JobPosting Course Review SoftwareApplication WebPage / WebSite

What It Checks

  • Presence of @context (must be schema.org)
  • Presence and validity of @type
  • All required fields per type (e.g. Article needs headline, author, datePublished)
  • Empty or null required fields
  • Invalid JSON syntax (reports exact line and column)
  • Unknown types (informational — not blocked)
  • Missing high-value types Google highlights for Rich Results

IndexNow Submission

IndexNow is a free protocol that lets you ping Bing, Yandex, and other search engines the moment you publish or update a page — no waiting for the next crawl.

One-Time Setup

Generate a key

Click Tools → IndexNow Submit → Generate. A 32-character hex key is created.

Upload the key file to your site

Create a text file at https://yourdomain.com/{key}.txt containing only the key string.

Save key in Settings

Go to Settings and save indexnow_key and indexnow_host — they auto-fill on every submission.

Submitting URLs

Once set up, paste URLs into the text area (one per line) and click Submit to IndexNow. Bulk batches of up to 10,000 URLs are supported in a single API call.

Content Generators

The Generators panel produces ready-to-copy SEO markup. Every generated snippet is validated before display — no broken JSON-LD, no malformed XML.

  • Meta Tags Generator: Enter your URL, title, and description — get correctly truncated <meta> tags with character counts shown live.
  • Schema Markup Generator: Choose a schema type, fill in the required fields, and get complete JSON-LD output validated against the spec.
  • Robots.txt Generator: Toggle rules for common bots (Googlebot, GPTBot, CCBot), set crawl delay and disallow paths, add your sitemap URL.
  • XML Sitemap Generator: Paste a list of URLs, choose changefreq and priority, download a valid sitemap.xml.
  • Hreflang Generator: Map language/region pairs to URLs and get the correct <link rel="alternate"> block including x-default.

Hosting Guide

SEO Suite is a stateful Python app with specific hosting requirements: it runs a persistent background thread (the scheduler), uses Playwright (Chromium), writes files to disk, and streams real-time SSE responses. This rules out most serverless platforms.

⚠ Serverless / Lambda / Vercel / Netlify are NOT compatible. Playwright requires a persistent process with Chromium installed, and SSE requires long-lived HTTP connections. You need a VM or container with always-on compute.

Production Deployment Checklist

  • Set SEO_SUITE_PASSWORD_HASH — never run on a public IP without auth
  • Place nginx or Caddy in front as a TLS-terminating reverse proxy
  • Set SEO_SUITE_COOKIE_SECURE=1 when serving over HTTPS
  • Configure a persistent volume for the /data directory (reports + history)
  • Set SENTRY_DSN for production error tracking
  • Use waitress or gunicorn -w 1 instead of Flask's dev server
  • Restrict CORS_ALLOWED_ORIGINS to your actual frontend domain
  • Set up log rotation for data/app.log

Security Architecture

SEO Suite v2.0.0 implements multiple layers of security for a tool that makes outbound HTTP requests on behalf of users.

LayerImplementation
SSRF ProtectionAll outbound URLs validated through core/security.py — blocks private IPs (10.x, 192.168.x, 172.16–31.x), loopback, link-local, cloud metadata endpoints
DNS Rebinding Guard_pinned_create_connection wraps urllib3's socket layer — re-validates the resolved IP at TCP connect time, not just at URL parse time
Redirect Validationsafe_requests_get/head/post re-validate every redirect hop — not just the initial URL
Rate Limitingflask-limiter: 10/hour on run endpoints, 20/minute on login
Path TraversalAll file access goes through _safe_report_path() — rejects ../ and symlinks outside REPORTS_DIR
Upload Limits10 MB max, CSV/XLSX only, column validation required
Authbcrypt-hashed password, httpOnly + SameSite=Lax session cookies, failed login logging
Settings Whitelist_SETTINGS_ALLOWED_KEYS — unknown keys silently dropped, never written to config
XSS PreventionAll user-controlled strings escaped via core.security.esc() before HTML report injection
